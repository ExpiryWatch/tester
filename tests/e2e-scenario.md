# Сквозной сценарий тестирования (E2E)

## Цель

Проверить совместную работу Frontend, Backend
и базы данных в рамках полного пользовательского
сценария приложения «Запасы».

## Предусловия

- Запущена объединённая версия приложения.
- Используется отдельная тестовая БД.
- Доступны категории и места хранения.
- Зафиксирован коммит проверяемой сборки.

## Сценарий E2E-01

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть приложение | Интерфейс загружается без ошибок |
| 2 | Добавить продукт «Молоко» с количеством 2 и будущим сроком годности | Продукт появляется в списке |
| 3 | Найти продукт по названию | Отображается нужный продукт |
| 4 | Изменить количество на 3 | Новое количество сохраняется |
| 5 | Попытаться установить количество 0 | Отображается ошибка, количество остаётся равным 3 |
| 6 | Изменить срок годности на прошедшую дату | Статус меняется на «Просрочен» |
| 7 | Включить фильтр просроченных продуктов | Продукт отображается в результатах |
| 8 | Проверить статистику | Счётчики соответствуют текущим данным |
| 9 | Обновить страницу | Данные сохраняются |
| 10 | Перезапустить приложение и сервер | Данные сохраняются |
| 11 | Удалить продукт | Продукт исчезает из списка |
| 12 | Проверить статистику и обновить страницу | Удалённый продукт не появляется, статистика обновлена |

## Результаты тестирования

- Дата:
- Коммит:
- Браузер:
- Статус: не проводилось.
- Обнаруженные дефекты:
- Комментарий:

## Критерий успешного прохождения

Все шаги выполнены, фактические результаты
соответствуют ожидаемым, данные сохраняются,
критические ошибки отсутствуют.
